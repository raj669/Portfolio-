case-study-1

A furniture retail e-commerce platform

Self-initiated QA testing on a live e-commerce platform, carried out alongside a separate primary role, as part of an internal systems role.

Scope: 109+ documented test cases (TC_01–TC_109) across authentication, product pages, mobile layout, promo banners, and the homepage.

What testing this platform turned up

Testing wasn't limited to the documented cases. Working through the platform end to end, alongside the structured suite, surfaced four real production defects:

  1. A 500 server error on native login
  2. Facebook OAuth login deactivated/non-functional
  3. Broken links on promotional banners
  4. A supplier watermark left visible on live product images

Each defect was documented and reported through the company's internal reporting channel to the responsible manager. The value here isn't just the count of bugs found — it's the combination of exploratory testing instinct (catching issues a scripted test wouldn't necessarily target, like a disabled OAuth provider) with structured documentation that a team can actually act on.

FAQ

What's your approach to writing test cases?

I start from the user flow, not the code. For the e-commerce testing, that meant walking through login, browsing, and checkout the way a real customer would, then writing test cases for each state, including the ones that aren't obvious, like what happens with a broken OAuth provider or a slow network.

Have you worked with test automation?

Yes. I built an API test suite with Playwright against the DummyJSON API and wired it into GitHub Actions so tests run on every push. Most of my testing background is manual, but I'm comfortable writing and maintaining automated test scripts.

How do you prioritize which bugs to report first?

Anything that blocks a core flow goes first, a login error that returns a 500 status stops everything downstream. After that, I look at visibility, a broken OAuth button or dead banner link is something every visitor sees.

Do you test across browsers and devices?

I've tested mobile layout specifically as part of my case study work. I don't have a large device lab, so I lean on browser dev tools and responsive testing to cover the common breakpoints, and I say so plainly if a claim needs a real device to confirm.

What testing tools and methods are you certified in?

I hold a QA and Software Testing certification from Broadway Infosys, completed December 2025 to February 2026, covering manual testing fundamentals, defect life cycle, and test case design.
